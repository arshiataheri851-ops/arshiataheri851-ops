# Portfolio Project Roadmap

This roadmap turns the portfolio's stated engineering focus into verifiable public work. A project should be pinned only after its implementation, setup instructions, tests, and limitations are documented.

## 1. Persian NLP — Sentiment & Text Classification API

**Purpose:** Demonstrate an end-to-end NLP workflow for Persian text.

**Core deliverables**
- Document the dataset source, license, intended use, and preprocessing steps.
- Establish a simple baseline before trying transformer-based models.
- Compare models using a documented train/validation/test split.
- Report appropriate metrics (for example macro-F1, per-class precision/recall, and confusion matrix).
- Package inference behind a FastAPI endpoint with input validation.
- Add unit tests, Docker support, and a concise model card.

**Definition of done**
- A reviewer can reproduce preprocessing and evaluation.
- Reported metrics are generated by committed evaluation scripts.
- The API can be run locally from documented commands.
- Known limitations and dataset bias are stated clearly.

## 2. Retrieval-Augmented Generation (RAG) Service

**Purpose:** Demonstrate grounded LLM application engineering, not just a chat interface.

**Core deliverables**
- Document ingestion and parsing pipeline.
- Configurable chunking and embedding steps.
- Retrieval layer with source metadata.
- Answers that cite retrieved source sections.
- Retrieval evaluation using a small, documented question set.
- FastAPI service, configuration through environment variables, and Docker setup.
- Tests for ingestion, retrieval, API validation, and failure cases.

**Definition of done**
- Each answer can be traced to retrieved context.
- Retrieval quality is evaluated separately from answer quality.
- Secrets are never committed.
- Model/provider limitations and operating costs are documented.

## 3. Production-Oriented ML Model Serving

**Purpose:** Show the engineering around a model after training.

**Core deliverables**
- A small, reproducible classification or regression model.
- Versioned training and evaluation pipeline.
- Model artifact loading and schema-validated inference endpoint.
- Structured logs, health checks, and latency measurements.
- Docker configuration and automated tests.
- A short architecture diagram and deployment notes.

**Definition of done**
- A fresh clone can reproduce the documented workflow.
- Tests cover valid input, invalid input, and model-loading failures.
- Metrics are measured by scripts and labelled with the environment used.
- No production deployment is implied unless one actually exists.

## 4. Real-Time Market Intelligence & Risk Analytics

**Purpose:** Demonstrate event/data processing and analytical software engineering.

**Core deliverables**
- Start with documented historical or synthetic OHLCV/order-book data.
- Ingestion, validation, and normalization pipeline.
- Feature computation and transparent signal definitions.
- Configurable monitoring and risk-alert rules.
- API endpoints and a simple dashboard or report.
- Tests for malformed, missing, and delayed data.

**Definition of done**
- Data provenance and assumptions are documented.
- Alerts are described as analytical signals, not investment advice.
- The pipeline can be run locally using documented sample data.

## Repository quality checklist

Before pinning any project:
- [ ] Clear problem statement and intended users.
- [ ] Architecture diagram and data-flow explanation.
- [ ] Reproducible setup instructions.
- [ ] Dependency and environment configuration.
- [ ] Tests and a visible test command.
- [ ] Evaluation methodology and actual measured results.
- [ ] Screenshots or a short demo where relevant.
- [ ] Limitations, security notes, and license.
- [ ] No credentials, private datasets, or confidential employer code.
