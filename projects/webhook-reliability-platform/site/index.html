The delivery lifecycle

Make every attempt observable.

A transport-agnostic event core with explicit state transitions and operational boundaries.

01 / INGEST

Idempotent intake

Accept events and create durable outbox records transactionally to reduce duplicate work from repeated producer requests.

02 / SIGN

Verified payloads

Canonical payloads are signed with HMAC-SHA256 and include a stable delivery identifier for receiver-side deduplication.

03 / DELIVER

Controlled retries

Bounded retry backoff, attempt history, leases and dead-letter handling help operators understand what happened.

Reliability, honestly stated

Resilient attempts. Clear delivery semantics.

RelayForge provides at-least-once delivery attempts—not exactly-once delivery. A receiver should deduplicate using the stable delivery ID.

Security boundaries

Constrain the path, protect the secret.

The implementation enforces HTTPS, port 443, exact hostname allowlisting, DNS answer validation and pinned-address connections. Production still requires infrastructure-level egress policy, secret management, monitoring and a security review.
